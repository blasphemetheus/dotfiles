# Contributing

This repo builds **two real machines**: `nixos_slanka` (Brad's desktop) and `aspire`
(the Acer laptop, Cole's). Most files are shared, so a change made on one machine lands
on the other the next time it pulls and rebuilds. Everything below follows from that.

## Your copy of the repo

Each person has their own clone at `~/dotfiles`, and the system builds from it:

| Command | Does |
|---|---|
| `nos` | `nh os switch`: builds `~/dotfiles` for this machine (picked by hostname) and shows a diff of what changed |
| `nrs` | `sudo nixos-rebuild switch --flake ~/dotfiles`: same build, plainer output |
| `./scripts/validate.sh` | evaluates **both** machines without building or switching anything |

Uncommitted edits count: `nos` builds whatever is in your working tree right now.
Files Git has never seen are invisible to the flake; `git add -N <file>` fixes that.

Some configs are **live-linked** (`hypr/`, `waybar/`, `kitty/`, `niri/`, `ags/`, `nvim/`,
`hyprwhspr/`): `~/.config/<app>` points straight into the repo, so edits there take effect
on reload with no rebuild. Everything else needs `nos`.

## The loop

```fish
cd ~/dotfiles
git switch main && git pull --rebase    # start from the latest
git switch -c cole/<short-topic>        # one branch per change

# ...edit...

./scripts/validate.sh                   # both machines still evaluate?
nos                                     # apply it here and try it

git add -A && git commit                # say *why* in the message
git push -u origin HEAD
gh pr create --fill                     # Brad reviews and merges
```

After the PR merges: `git switch main && git pull && nos`.

Your laptop can run your branch for as long as you like before the merge; the PR only
decides when the change reaches the desktop.

## Where a change belongs

| You want to change… | Edit | Affects |
|---|---|---|
| Something only for the laptop | `hosts/aspire/default.nix` | laptop only |
| Battery / idle / lid timings | `hosts/aspire/default.nix` (override `dotfiles.power.*`) | laptop only |
| Laptop keybinds | `hypr/.config/hypr/lua/binds-laptop.lua` | laptop only |
| System packages | `modules/system/packages.nix` | **both** |
| Shell, aliases, prompt | `modules/home/fish.nix`, `starship/` | **both** |
| Hyprland look, rules, shared binds | `hypr/.config/hypr/lua/*.lua` | **both** |
| Anything else in `modules/`, `configuration.nix`, `home.nix` | | **both** |

To keep a shared file's change on the laptop only, gate it on the profile:
`lib.mkIf (config.dotfiles.profile == "laptop") { ... }` in NixOS modules, or
`osConfig.dotfiles.profile` in Home Manager modules. Shared scripts can check for the
hardware they need and do nothing when it is missing (see `battery-monitor.sh`).

## Don't

- **Commit secrets.** API keys go in `~/.config/fish/secrets.fish`, which is not in git.
- **Run `nix flake update`** in a PR with other changes. It moves every package on
  both machines, and the Hyprland pins in `flake.nix` are deliberately held back. Ask first.
- **Edit `hosts/slanka/`** (the desktop) or **`hardware-configuration.nix`** by hand.
  The latter is generated by `nixos-generate-config`.
- **Change `system.stateVersion` / `home.stateVersion`.** They record the install, not the
  version you're running.
- **Push to `main` directly** (unless you own the repo). Use a branch and a PR.

## When a rebuild breaks something

- The build failed: nothing changed. Read the error, fix, run `nos` again.
- It switched but something's wrong: `sudo nixos-rebuild switch --rollback`.
- It won't boot to a desktop: pick an older generation in the boot menu (shown for a
  few seconds at power-on), then roll back.
- Hyprland is broken but the machine is fine: Ctrl+Alt+F2 for a text console, or choose
  the `niri` / `gnome (fallback)` session at the login screen.
- Want to try something risky first: `nixos-rebuild build-vm --flake ~/dotfiles#aspire`
  (see [TESTING.md](TESTING.md)).
